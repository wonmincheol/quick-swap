# Quick Swap — 기능 명세

## 목적

손에 든 벨트, 파이프, 전신주 계열 아이템을 마우스 휠로 빠르게 전환한다.
벨트·지하 벨트·분배기, 파이프·지하 파이프, 전신주를 각각 독립된 계열로
다루며, 플레이어의 현재 조작 상태에 따라 전환 후보와 아이템 소모 규칙을
달리한다.


## 입력

네 개의 재지정 가능한 Custom Input을 제공한다. 기본 키는 아래와 같다.

| 입력 | 기능 | 순방향 |
| --- | --- | --- |
| `Shift + 휠 위` | 빠른 아이템 전환: 다음 | 벨트 → 지하 벨트 → 분배기 → 벨트 |
| `Shift + 휠 아래` | 빠른 아이템 전환: 이전 | 위 순서의 역방향 |
| `Control + 휠 위` | 벨트 등급 전환: 상위 | 낮은 등급 → 높은 등급 |
| `Control + 휠 아래` | 벨트 등급 전환: 하위 | 높은 등급 → 낮은 등급 |

Shift 입력은 파이프 계열에서는 파이프와 지하 파이프 사이를 순환하고,
전신주 계열에서는 아이템 프로토타입의 정렬 순서에 따라 한 단계씩 이동한다.
Control 입력은 벨트 계열에만 적용된다.

`consuming = "none"`으로 등록하여 청사진 책자 전환을 포함한 바닐라 입력을
보존한다. 아이템 전환이 실제로 성공한 경우에만 현재 화면 배율을 최소·최대
줌 제한으로 잠근 뒤 다음 틱에 기존 제한값을 복원한다. 따라서 줌이 발생한 후
되돌아오는 과정 없이 카메라 이동 자체를 막는다. 전환 대상이 아니거나 전환에
실패하면 바닐라 줌 동작을 그대로 허용한다. Custom Input은 게임 설정에서
플레이어가 다시 배정할 수 있다. 이 문서에서는 두 조작 묶음을 각각
**빠른 아이템 전환**과 **벨트 등급 전환**이라고 부른다.
원격/지도 컨트롤러에서도 이벤트가 전달되도록 네 입력 모두
`enabled_while_spectating = true`로 등록한다.

## 전환 대상 판별

이름(`transport-belt`, `fast-transport-belt` 등)을 하드코딩하지 않는다.
손에 든 아이템의 `place_result`가 다음 엔티티 유형 중 하나일 때만 대상이다.

- `transport-belt`
- `underground-belt`
- `splitter`
- `pipe`
- `pipe-to-ground`
- `electric-pole`

따라서 타 모드가 추가한 배치 가능한 벨트·지하 벨트·분배기·파이프·지하
파이프·전신주도 자동으로 대상이 될 수 있다. 로더와 연결 벨트 등 위 유형에
포함되지 않는 엔티티는 이 버전의 범위에서 제외한다.

각 아이템은 **종류**(belt / underground / splitter)와 **티어**로 분류한다.
티어는 배치 결과의 `belt_speed`로 판별한다. 같은 속도의 일반 벨트·지하 벨트·
분배기는 같은 티어 묶음으로 취급한다. 같은 속도의 타 모드 후보가 여러 개면
내부 이름순으로 안정적으로 정렬한다. 이 규칙은 멀티플레이·리플레이에서도
동일한 결과를 보장한다.

## Shift: 종류 전환

벨트 계열에서는 현재 티어를 유지한 채 종류만 바꾼다.

```text
노란 벨트 ─Shift+휠 위→ 노란 지하 벨트 ─Shift+휠 위→ 노란 분배기
     ↑                                                        │
     └──────────────────────── Shift+휠 위 ──────────────────┘
```

예를 들어 파란 지하 벨트를 들고 있다면 같은 파란 티어의 분배기 또는
일반 벨트만 후보가 된다. 바로 다음 종류가 존재하지 않거나 사용할 수 없으면
같은 방향의 그다음 종류를 찾으며, 사용할 수 있는 다른 종류가 없을 때만
전환하지 않는다.

파이프 계열은 파이프와 지하 파이프 사이를 순환한다. 전신주는 아이템
프로토타입의 `order`와 내부 이름으로 정렬한 뒤 해당 방향에서 사용할 수 있는
다음 전신주를 선택한다. 사용할 수 없는 중간 전신주는 건너뛰며, 양 끝에서는
순환하지 않는다. 세 계열 사이를 넘나들어 전환하지 않는다.

## Control: 티어 전환

현재 종류를 유지한 채 티어만 바꾼다. 바닐라 기준 순서는 다음과 같다.

```text
노란 → 빨간 → 파란 → 초록(터보, Space Age가 있고 해금된 경우)
```

휠 아래는 역순이다. 따라서 `Control + 휠 위`로 일반 벨트는 일반 벨트인
채로, 지하 벨트는 지하 벨트인 채로, 분배기는 분배기인 채로 티어가 바뀐다.
Space Age가 없으면 초록 티어는 후보 목록에 없으며, 타 모드가 추가한 서로
다른 속도의 벨트 티어도 정렬된 목록에 포함한다. 최상위/최하위에서의 처리도
순환하지 않고 그대로 유지한다. 바로 다음 티어를 보유하지 않았으면, 해당
방향에서 보유한 다음 티어를 찾아 건너뛴다. 예: 노란 벨트에서 빨간 벨트가
없고 파란 벨트가 있으면 `Control + 휠 위`는 파란 벨트로 전환한다.

## 조작 상태별 아이템 규칙

### 캐릭터 조작 상태

`player.controller_type == defines.controllers.character`이고
`player.render_mode == defines.render_mode.game`인 일반 플레이 중에는
**플레이어 인벤토리에 실제로 있는 후보 아이템만** 전환할 수 있다.

- 후보 아이템이 없으면 전환하지 않는다.
- 후보 아이템이 1개라도 있으면 전환한다. 커서에는 현재 수량, 대상의 최대
  스택 수, 실제 보유 수량 중 가장 작은 수량을 든다. 예: 빨간 벨트 95개에서
  노란 벨트 94개로 바꾸면 노란 벨트 94개를 커서에 들고 빨간 벨트 95개는
  인벤토리로 돌려놓는다.
- 전환 시 기존 커서 스택을 인벤토리로 돌려놓고, 후보 스택을 커서로 옮긴다.
- 전환 전 아이템의 품질과 관계없이, 보유 중인 대상 아이템 가운데 품질 레벨이
  가장 높은 품질을 선택한다(예: 일반/희귀가 모두 후보면 항상 희귀 선택).
- 인벤토리 공간 부족으로 기존 스택을 되돌릴 수 없으면 전환하지 않는다.

이 방식은 아이템을 생성·삭제하지 않으며, 대상 아이템을 소지하지 않았는데도
건설할 수 있게 만들지 않는다.

### TAB/지도/원격 조작 상태

TAB으로 연 지도와 확대 지도(`chart`, `chart_zoomed_in`) 및 원격 컨트롤러에서는
인벤토리 보유 여부를 요구하지 않는다. 현재 플레이어의 force에서 **해금된**
같은 계열 후보라면 커서 스택을 해당 아이템으로 교체한다.

해금 판정은 해당 force에서 활성화된 레시피가 그 아이템을 생산하는지로
판단한다. 즉 아직 연구하지 않은 빨간·파란·초록 벨트는 후보가 아니며,
Space Age나 타 모드가 제공하는 벨트도 그 force에서 실제로 해금된 경우에만
후보가 된다. 품질 가용성은 Factorio의 원격 커서 품질 선택 규칙을 따르며,
모드가 현재 품질을 별도로 재판정하지 않는다. 전환에 성공하면 아이템 종류나
티어만 바꾸고 전환 직전 품질을 그대로 유지한다.
이 교체는 청사진·원격 건설 작업을 위해 아이템 보유량을 소비하지 않는다.
원격 건설 커서는 실제 `cursor_stack`이 아닌 `cursor_ghost`로 표현되므로,
지도 상태에서는 원격 커서의 아이템과 품질을 읽고 새 `cursor_ghost`를 설정한다.

## 보존 및 예외 규칙

- 빈 커서, 청사진·선택 도구·설정 도구는 무시한다.
- 캐릭터 상태에서는 대상 스택 한도와 실제 보유량 범위에서 수량을 정하고,
  보유 중인 대상 아이템의 최고 품질을 선택한다.
- TAB/지도/원격 상태에서는 전환 전 원격 커서의 품질을 유지한다.
- 멀티플레이에서는 각 플레이어의 커서와 force를 독립적으로 사용한다.
- DLC 또는 타 모드의 프로토타입을 수정하지 않는다. 단지 런타임에 존재하는
  아이템을 읽어 후보를 구성한다.
- 후보 판별 중 존재하지 않는 프로토타입, 비활성 레시피, 유효하지 않은
  Lua 객체는 안전하게 건너뛴다.

## 구현 구성

1. `data.lua`: 위 네 Custom Input을 정의한다.
2. `scripts/belt_catalog.lua`: 런타임 프로토타입에서 벨트·파이프·전신주
   카탈로그를 만들고 종류 또는 티어별 다음 후보를 찾는다.
3. `scripts/cursor_swap.lua`: 캐릭터/원격 상태별 전환과 수량·품질 보존을
   수행한다.
4. `control.lua`: 네 입력을 각 전환 함수에 연결하고, force별 레시피 해금
   여부와 성공한 전환의 일시적인 줌 잠금을 처리한다.

## 수용 기준

- 바닐라에서 노란/빨간/파란 벨트·지하 벨트·분배기가 위 입력 규칙대로
  전환된다.
- Space Age에서 해금된 터보(초록) 계열이 티어 전환의 최상단에 포함된다.
- Shift 입력으로 파이프와 지하 파이프가 서로 전환된다.
- Shift 입력으로 전신주가 정렬 순서에 따라 이동하고 양 끝에서는 순환하지
  않는다.
- 캐릭터 상태에서 인벤토리에 없는 후보는 절대 선택되지 않는다.
- TAB/지도/원격 상태에서 미해금 아이템은 절대 선택되지 않고, 품질은 게임의
  원격 커서 가용성 규칙을 따르며 기존 품질을 유지한다.
- 타 모드가 추가한 지원 대상 엔티티 유형의 배치 결과 아이템은 충돌 없이
  후보로 분류된다.
- 멀티플레이 호스트와 클라이언트에서 같은 입력이 같은 결과를 낸다.
