# Quick Swap 0.3.x 검증 기록

## 0.3.10/0.3.11 청사진 책자 조작 복구 — 2026-11-15

### 변경과 동작 선택

- 0.3.8/0.3.9의 기본 입력 차단으로 청사진 책자 전환이 막히는 회귀가 보고됐다.
- 사용자는 인벤토리 책자와 라이브러리에서 직접 집은 책자를 모두 사용하며,
  기존 Shift/Ctrl+휠을 유지하고 기본 게임 입력을 허용하는 방식을 선택했다.
- 네 입력을 항상 `consuming="none"`으로 등록하고 책자 전환·중첩 탐색은 기본 게임에 맡긴다.
  건설 아이템 전환 중 기본 줌도 함께 동작할 수 있다. 0.3.8/0.3.9의 줌 억제를 유지하는 패치는 아니다.
- 인벤토리 책자와 `cursor_record`는 Quick Swap 커서 변경에서 명시적으로 제외한다.
  라이브러리 책자를 인벤토리 복사본으로 교체하거나 원본 내용을 변경하지 않는다.
- `quick-swap-allow-vanilla-inputs` 설정을 제거해 이전 설정값이 꺼져 있던 환경에서도 입력을 허용한다.
- 최종 동작 결정: 기존 Shift/Ctrl+휠과 라이브러리 책자의 기본 전환을 유지하고,
  벨트 등 건설 아이템 전환 중 줌인·줌아웃을 허용한다. 사용자가 실제 동작을 확인한 뒤
  이 제약을 수용했으며, 현재 릴리스는 전환 중 줌 억제를 보장하지 않는다.

공식 [입력 소비 API](https://lua-api.factorio.com/latest/classes/LuaCustomInputPrototype.html#consuming)는
런타임에서 읽기 전용이며, [라이브러리 책자 선택 API](https://lua-api.factorio.com/latest/classes/LuaRecord.html#get_active_index)는
선택 인덱스 조회만 제공한다. 따라서 책자만 조건부로 소비를 해제하거나 선택을 대신 구현하지 않고 기본 조작을 보존한다.
확인한 2.1.24 공개 API 범위에서는 기존 키, 라이브러리 책자 원본 조작, 전환 중 줌 완전 차단을
동시에 안정적으로 보장할 수 있는 경로를 확보하지 못했다. 이 결론을 모든 향후 게임 버전에 대한 불가능 주장으로 일반화하지 않는다.

### 확인 결과

| 검증 | 결과 |
| --- | --- |
| Factorio 2.1.24 바닐라 자동 통합 검사 | 88개 및 저장 재로드 통과 |
| Space Age + F6~F9 키 재할당 자동 검사 | 90개, 키 표시 및 저장 재로드 통과 |
| 네 입력의 런타임 프로토타입 | 모두 `consuming="none"`, 원격 입력 활성화 확인 |
| 캐릭터·원격 보기의 인벤토리 책자 | 네 입력 핸들러 호출 후 책자 내용·선택·카메라 설정 보존 |
| 실제 휠로 인벤토리 책자 전환 | 양방향 선택 인덱스 `1→2→1` 확인 |
| 실제 휠로 라이브러리 책자 전환 | 캐릭터·원격 보기에서 양방향 `1→2→1` 확인 |
| 사용자 실게임 확인 | 라이브러리 책자 전환 정상, Shift/Ctrl+휠 벨트 전환 중 기본 줌 동작 확인 |

실제 휠 검사는 네 Quick Swap 입력과 기본 책자 전환을 같은 수정키 없는 휠에 재할당해
입력 충돌이 있는 조건에서 진행했다. 라이브러리는 게임 GUI에서 직접 집었고,
로그의 `cursor_record`가 `blueprint-book`인 상태와 기본 게임의 선택 변경을 확인했다.
이 검사는 물리 Shift/Ctrl을 누른 입력이나 중첩 책자 탐색을 직접 재현한 검사는 아니다.
모든 검증은 격리된 모드·설정·세이브에서 진행했으며 책자 GUI 검사는 클라우드 동기화를 껐다.

재현:

```powershell
python tools/test_runtime.py 'C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64\factorio.exe'
python tools/test_runtime.py 'C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64\factorio.exe' --space-age --rebound
```

사용자 실게임 확인은 위 항목에 기록한 범위다. 이번 릴리스의 실제 멀티 서버,
인벤토리·라이브러리·중첩 책자를 포함한 모든 키 조합의 전체 검사 및 Factorio 2.0 실행 파일 검증은 남아 있다.
아래 0.3.8/0.3.9의 사용자 멀티 확인 결과를 이번 릴리스 검증으로 간주하지 않는다.

## 0.3.8/0.3.9 입력 충돌 수정 — 2026-11-15

### 최종 결과

| 검증 | 결과 |
| --- | --- |
| Factorio 2.1.24 바닐라 자동 통합 검사 | 78개 및 저장 재로드 통과 |
| Space Age + F6~F9 키 재할당 자동 검사 | 80개, 키 표시 및 저장 재로드 통과 |
| 기본 게임 입력 허용 옵션을 켠 바닐라 자동 검사 | 78개 및 저장 재로드 통과 |
| 0.3.9 배포 ZIP의 실제 게임 로드 | 통과 |
| 사용자 싱글플레이 확인 | 전환 중 줌 떨림 해결 확인 |
| 사용자 실제 멀티 서버 확인 | 전환 중 줌 떨림 해결 확인 |

마지막 두 항목은 사용자가 보고한 실게임 결과다. 자동 검사가 실제 멀티 클라이언트를
구동해 얻은 결과와 구분한다. 접속 인원·네트워크 지연·전체 모드 구성별 개별 결과는
기록되지 않았으므로 모든 멀티 환경의 동기화·재접속·장기 안정성을 검증한 것으로 일반화하지 않는다.

### 자동 검사와 실제 휠 입력 검사

- 검증 실행 파일: Factorio 2.1.24. 아래 2.1.17 기록은 이전 릴리스의 결과다.
- 바닐라 78개, Space Age + F6~F9 재할당 80개 통합 검사와 각각의 저장 재로드 검사 통과.
- `quick-swap-allow-vanilla-inputs=true`인 바닐라 환경도 78개 통합 검사와 재로드 검사 통과.
- 네 입력의 실제 런타임 프로토타입에서 기본 `consuming="game-only"`, 호환 모드 `"none"`,
  원격 보기 입력 활성화를 확인했다.
- 캐릭터·원격 보기에서 네 방향 교체, 배열 끝, 사용 중지, GUI 위 입력, 재고 부족에 대해
  배율·기존 줌 제한이 유지되고 일시 잠금이나 `on_tick` 카메라 보정이 생성되지 않는지 검사했다.
- 이전 버전의 잠금 데이터를 주입한 뒤 실제 초기화 함수를 호출해 제한 복원과 데이터 제거를 확인했다.
  없는 플레이어의 잠금도 오류 없이 정리한다. 실제 구버전 저장 파일의 업그레이드 재현과는 구분한다.
- 별도 Space Age 테스트 창에 세로 단축키를 수정키 없는 휠로 재할당해 실제 휠 입력을 전달했다.
  캐릭터·원격 보기의 양방향 세로 교체와 캐릭터의 배열 끝 입력에서, 입력 직전부터 이후 15틱까지
  배율 범위가 모두 `1.0~1.0`이었다. 가로 교체도 동일한 입력 차단 정책의 비교본에서 배율 유지를 확인했다.
- 기본 게임 입력 허용 옵션을 켜고 책자 순환과 Quick Swap을 같은 휠에 재할당한 별도 창에서,
  실제 양방향 휠 조작으로 청사진 선택 인덱스 `1→2→1`과 건설 미리보기 변경을 확인했다.
- 이 실제 휠 검사는 수정키를 누른 물리 입력을 그대로 재현한 검사가 아니다.
  실제 사용 환경의 줌 떨림 해결 여부는 위의 사용자 싱글·멀티 확인 결과로 기록한다.

### 수정 내용과 호환성

- 기존 코드는 `consuming="none"`으로 기본 입력을 통과시키고, 성공한 교체에서 줌 제한을
  잠근 뒤 다음 틱에 복원했다. 이번 수정은 이 카메라 변경 경로를 제거하고 기본 입력을 먼저 차단한다.
- 기본 설정에서는 교체 불가·배열 끝·사용 중지 상태에서도 네 전환 단축키를 전용으로 사용한다.
  수정키 없는 기본 휠 줌은 유지하며 청사진 책자처럼 같은 단축키의 기본 게임 동작은 차단한다.
- 시작 설정 `quick-swap-allow-vanilla-inputs`를 켜면 기본 조작과 함께 교체 중 줌도 허용한다.
- 이전 저장에 남은 일시 줌 잠금은 업그레이드 초기화에서 복원하고 제거한다.
- GUI 위에서 발생한 입력은 아이템 전환을 실행하지 않는다.

공식 [CustomInputPrototype 문서](https://lua-api.factorio.com/2.1.24/prototypes/CustomInputPrototype.html#consuming)와
[ConsumingType 문서](https://lua-api.factorio.com/2.1.24/types/ConsumingType.html)가 입력 통과·차단 정책의 근거다.

멀티에서는 서버와 클라이언트에 같은 릴리스를 적용해야 한다. 0.3.7 서버에 맞춰 동기화하면
수정 전 코드가 실행되므로 0.3.9의 검증으로 볼 수 없다. 각 시작 로그와 모드 설정을 확인한 뒤
테스트해야 하며, 실행 중 ZIP 교체만으로는 이미 로드한 입력 프로토타입이 변경되지 않는다.

### 남은 검증 범위

- Factorio 2.0 실행 파일에서의 실게임 검증. 현재 자동 검증 환경은 2.1.24다.
- 다양한 외부 모드·네트워크 지연 조건의 멀티 동기화, 재접속 및 장시간 사용.
- 대규모 그룹 배열과 실제 외부 모드 제거 후의 사용성·성능.

아래 명령은 0.3.8/0.3.9 검증 당시 스크립트 기준이며, 모두 임시 모드·세이브·설정을 사용했다.

## 이전 릴리스 검증 (0.3.0~0.3.7)

검증일: 2026-09-13

### 실행 환경과 결과

- 설치된 Factorio 2.1.17 실행 파일을 사용했다.
- 0.3.0/0.3.1 초기 구현: 바닐라 41개, Space Age 43개 통합 검사 및 재로드 검사 통과.
- 0.3.2/0.3.3 편집 개선: 바닐라 63개, Space Age 65개 통합 검사 및 재로드 검사 통과.
- 0.3.4/0.3.5 위치 편집 제거: 바닐라 55개, Space Age 57개 통합 검사, 키 재할당 및 재로드 검사 통과.
- 0.3.6/0.3.7 배포 전 정리: 바닐라 57개, Space Age 59개 통합 검사, 키 재할당 및 재로드 검사 통과.
- 별도 키 재할당 검사에서 F6~F9로 설정한 네 방향 키가 게임의 번역 결과와 화면에 표시되는 것을 확인했다.
- 실제 게임 GUI 캡처에서 그룹 제목줄, 10칸 배열, 자동 추가된 빈 행,
  전체 사용 설정, 순환 설정, 하단 안내와 적용·취소 버튼을 확인했다.
- 테스트는 임시 모드·세이브·설정 디렉터리에서 실행했다. 사용자 모드 및 세이브는 수정하지 않았다.

### 자동으로 확인한 동작

- 기본 그룹 생성, 일반 건설 아이템 지원, 청사진 제외, 초기 연구 해금 판정.
- 가로·세로 이동, 가로 순환, 세로 끝 정지, 빈칸·빈 행 건너뛰기.
- 그룹 우선순위, 다른 그룹으로 넘어가지 않는 동작, 전체 사용 중지.
- 실제 GUI 생성, 10열 고정, 마지막 행 사용 시 빈 행 생성, 끝의 빈 행 정리.
- 같은 그룹 내 중복 거부, 미해금 아이템 등록 거부.
- 사라진 아이템의 좌표 유지와 우클릭으로 해당 슬롯 비우기.
- 그룹 추가·이름 변경·삭제, 임시 편집, 적용·취소, 닫을 때 변경 폐기 확인.
- 플레이어별 설정 분리(서로 다른 플레이어 인덱스의 저장 데이터).
- 정상 인벤토리 교체와 수량 보존, 인벤토리 포화 시 부분 삽입의 정확한 롤백.
- 입력 핸들러 연결, 성공 시 줌 잠금 및 다음 틱 복원, 편집 창을 연 동안 전환 중지.
- 원격 커서 교체, 연구 변경 후 해금 목록과 캐시된 선택기 필터 갱신.
- Space Age에서 최고 보유 품질 선택과 원격 커서의 전설 품질 유지.
- 실제 저장 파일 재로드 후 설정과 열린 편집 창 유지.
- 그룹 위·아래 이동과 경계 버튼, 화면 순서·데이터 순서·탐색 우선순위의 일치.
- 위치 편집 UI가 없고 기본 선택기가 잠기지 않으며 일반 클릭이 이동 출발 칸을 선택하지 않는지 확인.
- 우클릭 비우기와 취소 시 슬롯 복원 확인.
- 그룹 순서를 변경한 실제 저장 파일을 재로드해 순서와 기존 슬롯 위치 유지 확인.

### 사용자 수동 테스트 결과

0.3.0/0.3.1 초기 구현을 원격 데스크톱 환경에서 사용자가 확인한 결과다. 아래 내용은 자동 검사 결과와 구분한다.
사용한 외부 모드명과 게임 버전은 별도로 기록되지 않았다.

- 다른 키보드 키로 입력을 재할당했을 때 정상 동작했다.
- 원격 환경에 마우스를 추가해 Shift/Ctrl+휠 입력도 정상 동작하는 것을 확인했다.
  이후 사용자가 로컬 환경에서도 정상 동작을 확인했다(아래 추가 확인 참조).
- 바닐라·DLC 아이템뿐 아니라 외부 모드가 추가한 새로운 아이템에서도 전환이 동작했다.
- 일반 캐릭터와 지도·원격 보기의 아이템 사용 규칙이 모드 아이템에서도 정상 동작했다.
- 배열 경계, 빈칸·사용 불가 항목 건너뛰기, 축별 순환 및 그룹 중복 처리에 문제가 없었다.
- 테스트한 모드 아이템의 해금 처리에 문제가 없었다.
  레시피 없이 지급되는 모든 특수 아이템까지 지원한다고 일반화하지 않는다.
- 팝업에서 적용한 뒤 게임을 저장하고 여러 번 종료·재실행했을 때 설정이 유지됐다.
- 실제 멀티플레이 테스트는 추후 진행하기로 했다.

추가 사용자 확인: 이동·교환 기능 제거 후 로컬 환경에서도 문제없이 작동함을 확인했다.
개별 검사 항목과 게임 버전은 별도로 전달되지 않았으며, 멀티플레이 확인을 의미하지 않는다.

설정 적용은 현재 게임 상태에 반영하는 단계이며, 재실행 후 보존하려면 해당 게임을 저장해야 한다.

### 재현

```powershell
python tools/test_runtime.py 'C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64\factorio.exe'
python tools/test_runtime.py 'C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64\factorio.exe' --space-age
python tools/test_runtime.py 'C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64\factorio.exe' --rebound
python tools/test_runtime.py 'C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64\factorio.exe' --space-age --rebound
```

스크립트는 임시 복사본에만 테스트 진입점을 추가하고, 테스트용 게임 프로세스만 종료한다.
GUI 검증을 위해 숨김 창으로 그래픽 클라이언트를 실행하고, 재로드는 헤드리스 벤치마크로 확인한다.
스크린샷은 `dist/tests`에 저장한다. 테스트 코드는 배포 ZIP에서 제외한다.

### 남은 수동 검증 범위

당시 배포 결정: 해당 검증 결과로 배포를 진행하고, 멀티플레이와 다양한 모드 구성·사용 상황은
배포 후 사용자 피드백을 받아 추가 검증한다. 아래 항목은 검증 완료로 간주하지 않는다.

- Factorio 2.0 실행 파일에서의 실게임 검증: 당시 설치 환경에는 2.1.17만 있었다.
- 두 실제 멀티플레이 클라이언트의 동기화와 재접속.

  자동 검사는 GUI 이벤트와 입력 핸들러를 게임 API로 호출한다.
- 실제 외부 모드 제거 후 사라진 아이템 슬롯 처리. 자동 검사에서는 없는 아이템 이름으로 확인했다.
